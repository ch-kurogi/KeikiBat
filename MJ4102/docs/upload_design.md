# MJ4102 アップロード処理 設計書

## 1. 概要

| 項目 | 内容 |
|------|------|
| 機能コード | MJ4102 |
| 機能名称 | アップロード完了監視 |
| 目的 | タブレット端末から送信された施工・抜取検査の結果ファイルを監視し、DBへ取り込む |
| 対象システム | 計器定期取替システム |

---

## 2. 処理概要

タブレット端末が NAS 上の所定フォルダへアップロードしたZIPファイルを検知し、以下を行う。

1. アップロードファイルの存在確認・バックアップ
2. ファイルの復号化・解凍
3. CSVファイルの読み込み
4. DBテーブルの更新（トランザクション）
5. 後処理（ファイル削除・WEBAPI実行管理登録）

処理対象は **施工** と **抜取検査** の２区分であり、事業所単位でループ処理する。

---

## 3. 起動仕様

### 3.1 起動コマンド

```
MJ4102.exe <接続先コード> [<処理年月日>] [<事業所コード先頭文字>...]
```

### 3.2 コマンドライン引数

| 引数番号 | 内容 | 必須 |
|----------|------|------|
| 1 | 接続先コード（INSTANCE_CD） | ○ |
| 2 | 処理年月日（YYYYMMDD）省略時はシステム業務日付を使用 | - |
| 3 以降 | 対象事業所コードの先頭1文字（省略時は全事業所対象） | - |

### 3.3 DB接続

- 最大 `C_MAX_RETRY`（10回）まで1秒間隔でリトライする。
- 接続は UTF8 エンコーディングで行い、`set client_encoding = UTF8` を明示的に実行する。

---

## 4. 処理フロー

### 4.1 全体フロー

```
Main()
 ├─ コマンドライン引数取得
 ├─ DB接続（リトライあり）
 ├─ MJ4102.MainLogic() 呼び出し
 │    ├─ 事業所マスタ取得（COM_ZGSYO_MST）
 │    └─ 機能使用可能時間帯ループ（CanUseKino）
 │         ├─ バッチ終了ファイルチェック
 │         ├─ 事業所ループ
 │         │    ├─ UpldTrkmKekka（施工）
 │         │    └─ UpldTrkmKekka（抜取検査）
 │         └─ Sleep（1,000ms）
 └─ DB切断・終了コード返却
```

### 4.2 UpldTrkmKekka（監視・取込処理）フロー

```
UpldTrkmKekka(事業所コード, 施工 or 抜取検査)
 ├─ アップロードパス・バックアップパスの設定
 ├─ 監視パス（ctr/）の存在確認
 ├─ 作業パス（tmp/）の作成
 ├─ 完了ファイル（END_*）一覧取得
 └─ 完了ファイルごとのループ（最大 C_PROC_MAX_FILES=1件/回）
      ├─ ファイル名解析
      │    └─ END_[端末番号]_[ユーザID]_[バージョン]_[YYYYMMDDHHMMSS]
      ├─ 現行アプリバージョン取得
      ├─ メジャーバージョン相違チェック
      │    └─ 旧バージョンの場合：旧バージョンフォルダへ移動→スキップ
      ├─ 完了ファイルを作業パスへ移動
      ├─ アップロードZIPファイルの存在確認
      ├─ バックアップコピー（バックアップ未存在の場合のみ）
      ├─ バッチサーバ展開パスへZIPをコピー
      ├─ 復号化（DecryptFile）
      ├─ 解凍（ExpandArchive）
      ├─ DBトランザクション開始
      ├─ テーブル更新
      │    ├─ 施工：updateDataSeko()
      │    └─ 抜取検査：updateDataNktrKns()
      ├─ コミット or ロールバック
      └─ 後処理（ZIPファイル削除・展開フォルダ削除）
```

## 7. テーブル更新仕様

### 7.1 施工（低圧）テーブル更新シーケンス

```
updateDataSeko()
 ├─ 取替票ファイル読込（低圧 or 高圧他を自動判定）
 ├─ updateTRKE_TRKEHY_TIAT()
 │    ├─ 行程管理コードチェック（C040:取替票受信済 or Fxxx:他異動）
 │    ├─ 廃滅登録重複チェック（SMJ計器情報と撤去計器指示数を突合）
 │    ├─ 取付計器 第２世代チェック（MAM計器設定との指示数突合）
 │    ├─ TRKE_TRKEHY_TIAT テーブル更新（U001）
 │    ├─ updateDataSekoOthers()
 │    │    ├─ KEIKI_JUJU_RIREKI 更新
 │    │    ├─ TRKE_TRKEHY_PRC 更新（U002）
 │    │    ├─ TRKE_TRKEHY_TUIKAKH 更新
 │    │    ├─ TRKE_CHECK_SHEET 更新
 │    │    └─ COM_TNPDOC_DTL 更新（添付画像含む）
 │    ├─ ダウンロード取替票管理 持出ファイル状態を「5:アップロード済」に更新（U011）
 │    └─ WEBAPI実行管理テーブルへ登録（I011）
 │         ├─ IF023 取付完了通知
 │         ├─ IF024 撤去完了通知
 │         └─ IF025 設備情報更新（端子部再用の場合）
 └─ ログファイル登録
      ├─ COM_KIFRFLG
      ├─ COM_LOG_SYUSYU
      ├─ COM_LOGIN_NNSY_RK
      └─ COM_LOGIN_RIREKI_DATA
```

### 7.2 行程管理コードの遷移

| 取込前 | 条件 | 取込後 |
|--------|------|--------|
| C040（取替票受信済） | CTなし | D020（竣工報告待） |
| C040（取替票受信済） | CT付き（計器種別分類コード = CT） | D010（竣工結果確認待） |
| Fxxx（他異動中止系） | - | 変更なし（更新日時のみ更新） |

### 7.3 バリデーションチェック一覧（低圧）

| チェック内容 | エラー時の動作 |
|------------|--------------|
| 取替票レコードが存在しない | エラー終了 |
| 行程管理コードが不正（手入力フラグOFF） | 警告フラグON・対象取替票をスキップ |
| 行程管理コードが不正（手入力フラグON） | スキップ（警告フラグ立てない） |
| アップロードバージョンが旧メジャーバージョン | 旧バージョンフォルダへ移動・スキップ |
| 廃滅登録重複かつ撤去計器指示数不一致 | エラー終了 |
| 廃滅登録重複かつ庫出日あり・庫入日なし | エラー終了 |
| 廃滅登録重複かつ庫出日 >= 庫入日 | エラー終了 |
| 取付計器が第２世代かつMAM指針との不一致 | エラー終了 |

## 9. エラー処理・監視

### 9.1 エラー処理方針

- テーブル更新はトランザクション単位（アップロードファイル1件）でコミット/ロールバックする。
- ファイル取込エラー発生時は Zabbix へメッセージを送信し、監視システムに通知する。
- 警告フラグ（`pWarningFlg`）が立った場合でも処理は継続する（次のファイルへ進む）。
- 異常フラグ（`wAbnormalFlg`）が立った場合は `ExitCode.Abnormal` を返却する。

### 9.2 Zabbix 通知を行うエラー種別

| エラー内容 |
|-----------|
| アップロード完了ファイルが存在しない |
| アプリバージョン取得エラー |
| アップロードファイルが旧バージョン（翌営業日メッセージ） |
| アップロードファイルが存在しない |
| アップロードファイル復号化エラー |
| アップロードファイル展開エラー |
| アップロードファイル取込エラー |

### 9.3 バッチ強制終了

バッチ終了フォルダ（`{K1TEMP}/BAT/`）に以下のファイルが存在する場合、処理ループを抜けて正常終了する。

| ファイル名 | 説明 |
|-----------|------|
| `MJ4102` | 全インスタンス終了 |
| `MJ4102_{ユーザID}` | 特定ユーザのインスタンス終了 |

終了確認として `END_MJ4102_{PID}` ファイルを作成する。
